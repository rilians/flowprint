---

# 1. Executive Summary

FLOWPRINT is a web-based business process intelligence platform designed to help organizations understand, analyze, and optimize their operational workflows.

The platform enables users to visually map existing business processes, measure operational effort, identify bottlenecks, discover automation opportunities, simulate improved workflows, and generate structured optimization reports.

Unlike conventional project management software, FLOWPRINT does not primarily manage tasks or employee productivity. Its core purpose is to analyze how work is performed and identify how that work can be simplified, standardized, or automated.

The product transforms process improvement from a subjective activity into a structured, measurable, and evidence-supported decision-making process.

## Product Vision

Make business process improvement understandable, measurable, and accessible through visual process intelligence.

## Core Value Proposition

FLOWPRINT helps users answer five important questions:

1. How does our current process actually work?
2. Where are the inefficiencies and bottlenecks?
3. Which activities should be simplified or automated first?
4. What would the improved process look like?
5. How much time and operational cost could potentially be saved?

# 2. Problem Statement

Many organizations still perform repetitive operational activities using manual procedures, spreadsheets, emails, and disconnected tools.

These conditions create several problems:

- Business processes are poorly documented.
- Repetitive activities consume unnecessary working hours.
- Managers cannot easily identify operational bottlenecks.
- Automation initiatives are often selected without sufficient analysis.
- Organizations struggle to estimate the potential benefits of process improvement.
- Process documentation and management reports are disconnected from operational data.

There is a need for a platform that connects process visualization, operational analysis, automation discovery, and impact simulation in one environment.

## Proposed Solution

FLOWPRINT provides an integrated environment where users can document current workflows, analyze operational characteristics, receive rule-based improvement recommendations, and construct optimized future workflows.

# 5. Core Product Modules

## MODULE 01 — Process Studio

### Purpose
Provide a visual environment for creating and editing business process workflows.

### Main Interface

The Process Studio consists of three primary sections:

**A. Left Panel — Node Library**

Available components:

- Start Node
- Activity Node
- Waiting Node
- End Node

Each component can be dragged onto the canvas.

**B. Center Panel — Workflow Canvas**

The primary workspace where users construct process maps.

Required capabilities:

- Drag-and-drop node placement.
- Connect nodes using directional edges.
- Move and reposition nodes.
- Zoom in and out.
- Pan across the canvas.
- Grid background.
- Mini-map.
- Fit-to-screen control.
- Delete and duplicate nodes.
- Undo and redo.
- Save and restore workflow state.

**C. Right Panel — Node Inspector**

When a node is selected, display its editable properties.

For Activity Nodes:

| Property | Description |
|---|---|
| Activity Name | Name of the operational activity |
| Description | Activity explanation |
| Responsible Role | Person or department responsible |
| Execution Mode | Manual, Semi-Automated, Automated |
| Human Effort | Hands-on working time in minutes |
| Waiting Time | Time spent waiting in minutes |
| System / Tool | Application or tool currently used |
| Repetition Score | Repetitiveness, scale 1–5 |
| Standardization Score | How standardized the task is, scale 1–5 |
| Error Impact | Operational impact of errors, scale 1–5 |

For Waiting Nodes:

- Waiting Activity Name
- Description
- Waiting Duration
- Responsible Department (optional)

Start and End Nodes only require a label.

### Workflow Validation

A valid MVP workflow must:

- Contain exactly one Start Node.
- Contain exactly one End Node.
- Have a valid connected path from Start to End.
- Contain no cycles.
- Have no disconnected activity nodes.
- Follow a linear execution sequence.

The MVP intentionally uses linear workflows. Branching and gateway logic are reserved for a future release so that time and cost calculations remain predictable and transparent.

### Autosave

- Automatically save changes after a short debounce period.
- Show saving, saved, and save-error indicators.
- Restore the previous saved workflow when the user reopens the project.
- Avoid data loss when switching modules.

## MODULE 03 — Automation Discovery

### Purpose
Identify activities that should be considered for automation, simplification, integration, or standardization.

### Automation Opportunity Score

Every Activity Node receives a score from 0 to 100.

The score is calculated using the following transparent heuristic:

| Factor | Weight |
|---|---:|
| Monthly Process Volume | 20 |
| Manual Work Intensity | 20 |
| Repetitiveness | 20 |
| Standardization Readiness | 15 |
| Waiting Time | 10 |
| Error Impact | 10 |
| Digital Integration Readiness | 5 |
| **Total** | **100** |

Scoring rules:

- Every factor is normalized to a range of 0–1.
- The final score is the sum of each normalized factor multiplied by its weight.
- Manual work receives a higher score than semi-automated or fully automated work.
- High-frequency, repeatable, standardized activities receive higher priority.
- Long waiting time and high error impact contribute to improvement priority.

For the monthly volume factor:

`Volume Score = min(monthlyVolume / 500, 1)`

For 1–5 scale inputs:

`Normalized Score = (value - 1) / 4`

For manual work intensity:

- Manual = 1
- Semi-Automated = 0.5
- Automated = 0

For waiting time:

`Waiting Score = min(waitMinutes / 120, 1)`

Digital integration readiness uses a 1–5 scale.

### Opportunity Classification

| Score | Classification |
|---|---|
| 75–100 | High Priority |
| 55–74 | Medium Priority |
| 0–54 | Low Priority |

The score is a prioritization heuristic, not a statistical prediction of automation success.

### Recommendation Categories

The rule-based recommendation engine can recommend:

**1. Automate**

For repetitive, high-volume, standardized manual activities.

**2. Simplify**

For activities with unnecessary complexity or excessive operational effort, when the user has identified that complexity.

**3. Standardize**

For activities with low standardization readiness.

**4. Integrate**

For activities involving repeated data transfer between systems.

**5. Reduce Waiting**

For activities with significant waiting periods.

### Recommendation Card

Each card must display:

- Activity name.
- Opportunity score.
- Priority classification.
- Recommendation category.
- Reason for recommendation.
- Evidence from process input fields.
- Suggested solution.
- Potential impact.
- Action button: Add to Scenario.
- Action button: Dismiss.

Users must be able to review, accept, dismiss, or revisit recommendations.

Do not use AI-generated claims or fabricate operational insights. The MVP uses a deterministic rule engine. An AI integration may be added in a future version.

## MODULE 04 — Scenario Simulator

### Purpose
Allow users to construct and compare an improved process against the existing process.

This is one of FLOWPRINT's most important differentiators.

### A. Scenario Creation

Users can:

- Create a new improvement scenario.
- Duplicate the existing workflow.
- Add, remove, or rearrange activities.
- Modify activity execution modes.
- Modify human effort.
- Modify waiting times.
- Apply recommended improvements.

The original As-Is process must remain unchanged.

### B. Before vs After Comparison

Display side-by-side comparisons of:

| Indicator | Current Process | Proposed Process |
|---|---|---|
| Total Activities | Calculated | Calculated |
| Manual Activities | Calculated | Calculated |
| Human Effort / Run | Calculated | Calculated |
| Waiting Time / Run | Calculated | Calculated |
| Monthly Labor Hours | Calculated | Calculated |
| Monthly Labor Cost | Calculated | Calculated |

### C. Impact Estimation

Calculate:

**Time Saved per Execution**

`Current Human Effort - Proposed Human Effort`

**Monthly Hours Saved**

`(Current Effort - Proposed Effort) × Monthly Volume / 60`

**Potential Monthly Hours Saved After Adoption**

`Monthly Hours Saved × Adoption Rate`

**Potential Monthly Cost Savings**

`Potential Monthly Hours Saved After Adoption × Hourly Labor Cost`

**Estimated Payback Period**

`One-Time Implementation Cost / Potential Monthly Cost Savings`

Return an unavailable or not-applicable result when savings are zero or negative.

### D. User-Adjustable Assumptions

- Monthly execution volume.
- Hourly labor cost.
- Estimated adoption rate.
- One-time implementation cost.

Clearly label the results as estimates based on user-defined assumptions.

### E. Scenario Management

Users can:

- Save multiple scenarios.
- Rename scenarios.
- Duplicate scenarios.
- Delete scenarios.
- Compare a selected scenario with the baseline.
- Return to the original process.

# 11. Calculation Methodology

The MVP supports linear workflows.

### Process Human Effort

`Total Human Effort = Sum of all Activity Effort Minutes`

### Process Waiting Time

`Total Waiting Time = Sum of all Wait Node Minutes + Activity Waiting Minutes`

### Cycle Time

`Cycle Time = Total Human Effort + Total Waiting Time`

### Monthly Human Workload

`Monthly Hours = (Total Human Effort / 60) × Monthly Volume`

### Monthly Labor Cost

`Monthly Cost = Monthly Hours × Hourly Labor Cost`

For future scenarios, the same calculations are applied to the proposed process graph.

### Potential Savings

`Potential Monthly Hours Saved = (Baseline Monthly Hours - Proposed Monthly Hours) × Adoption Rate`

`Potential Monthly Cost Savings = Potential Monthly Hours Saved × Hourly Labor Cost`

### Payback Period

`Payback Months = Implementation Cost / Potential Monthly Cost Savings`

All calculation functions must be centralized in a dedicated calculation service, not scattered across UI components.

Calculations must be unit-tested and must handle invalid values, missing data, and negative savings.

# 12. Non-Functional Requirements

### Performance
- Avoid unnecessary full-page rerenders when editing nodes.
- Debounce autosaving.
- Keep the canvas responsive when handling moderately sized workflows.
- Use lazy loading for heavier reporting or visualization components where beneficial.

### Usability
- Clear visual hierarchy.
- Intuitive node editing.
- Consistent labels.
- Useful tooltips.
- Accessible keyboard interaction.
- Responsive application layout.

### Security
- Use authenticated server-side access where applicable.
- Apply database Row Level Security.
- Validate incoming data on the server.
- Never expose service-role keys to the client.
- Keep environment secrets outside the repository.

### Reliability
- Autosave must report failures visibly.
- Prevent accidental loss of the original process.
- Validate workflows before analysis.
- Provide confirmation before destructive actions.

# 15. Acceptance Criteria

The MVP is considered complete when:

1. A user can access and explore a populated demo environment.
2. A user can create a process and configure its basic information.
3. A user can add, edit, move, connect, duplicate, and delete process nodes.
4. The process graph can be saved and restored.
5. Invalid workflows are rejected with clear explanations.
6. Valid workflows generate correct process metrics.
7. Opportunity scores are calculated from actual node inputs.
8. Recommendations explain the factors behind their scores.
9. A user can create a separate To-Be scenario.
10. Changes to the scenario do not overwrite the original process.
11. Before/after metrics update when the scenario changes.
12. Cost savings and payback calculations use the documented formulas.
13. Reports can be previewed and printed to PDF.
14. Process information can be exported.
15. The interface works on desktop and tablet.
16. Core functions do not rely on decorative or non-functional buttons.
17. Empty, loading, and error states are properly implemented.
18. Database security policies protect users' data.
